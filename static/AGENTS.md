# 输出纪律（my_pi 全局规则）

以下规则对**所有项目**生效，项目级 AGENTS.md 可在此基础上追加，但不得推翻。加入本文件的条件：任何项目、任何体裁下都成立；只适用于某类项目的规则留在对应项目的 AGENTS.md 或按需加载的 skill 里。

## 1. 解释进对话，产物只含产物

- 所有解释、设计理由、技术说明、给开发者的提示，只出现在对话回复中，**绝不写入交付物**（代码、注释、UI 文案、文档、发布文本）。
- 交付物的内容只面向它的最终受众（应用用户/读者），默认他们不了解也不关心实现细节。
- 需要向开发者说明的内容，写在对话回复的「说明」区；write/edit 工具写入的内容视为交付物，写入前自检受众。

## 2. 注释只写当前状态与「为什么」

- 不记变更史（"改为""之前是""本次新增"归 git 和 commit message）。
- 是否加注释取决于该处读者是否需要，而非默认补充；显而易见的代码不加，不用括号注释解释常识。

## 3. 文案纪律：受众代入自查

- UI 文案、公告、发布文本等面向最终用户的内容，禁止出现解释实现方式、内部机制、开发决策的句子。
- 按钮、标签、菜单项、表头这类长度受限的短文本，只写核心动作或名词，不写完整句子；括号只留给单位、范围、版本这类必要区分项，不用它塞补充解释。
- 输出此类文案前，以"第一次看到它的目标用户"视角自查：每一处该用户不可能看懂或不需要知道的解释，删除。
