# lean-review：AI 产出审查

先判对象，走对应模式。

| 对象 | 模式 | 判据 | 动作 |
|---|---|---|---|
| 代码、注释、提示词、开发文档 | 删冗余（下四张表） | 删掉它会损失什么？ | 删掉多余的部分 |
| 成稿散文：文章、报告、公告、公众号、汇报稿 | 去 AI 味 | 看到什么标记就标记 | 信息不增不减，只换句式 |

两模式共享下面两条硬约束和输出格式。**每处改动都要能指回一条规则，指不出就撤销。**

## 硬约束一：误伤区（不得作为改动理由）

实测这些特征人类写得比 AI 更多，或差别测不出来。照直觉改只会更像 AI。

| 特征 | 为什么不能改 |
|---|---|
| 句长、段落长度不够参差 | 与人类无差别。不要为制造节奏调句长或拆段 |
| 单字虚词偏少（就／很／了） | 方向是补不是删。补虚词无法验收，容易把正式文章改成口语 |
| 反复写全称、少用代词 | 人类比 AI 更常重复同一名词 |
| 被动句、名词化、长句本身 | 现代汉语书面语的正常写法，人类同样这么用 |
| 正文设问、反问、问句小标题 | 人类是 AI 的 17 倍，删掉更不像人写 |
| 比喻、比喻独立成段 | 人类是 AI 的 2.4 倍，独立成段是 8 倍。只处理理想化拟人喻体 |
| 句内同构排比（「提升效率，降低成本」） | 人类用得不比 AI 少。只处理句间重复 |
| 正文里的「首先……其次」 | 与人类无差别。规则只管小标题编号 |
| 抽象名词配具体动词 | 两边都几乎不写 |

## 硬约束二：信息守恒

- 不许新增原文没有的内容：姓名机构、数字金额、日期与先后、引语、来源、因果与动机、细节场景。
- 不许删观点、结论、限定词与让步（「可能」「通常」「据说」）。把「可能提升」改成「提升」属加重语气，不是去 AI 味。
- 检验方法：改写后每处表述都要能在原文指出出处，指不出就是新增，撤销。
- 「把抽象写具体」不是本 skill 的职责，原文抽象就让它抽象。

## 删冗余

AI 生成的内容有几类典型冗余。下表给**术语 + 判据 + 修法**，诊断时用术语指称问题，不说「有点啰嗦」这类模糊话。

流程：① 确定对象（用户指定的文件／diff／文案；未指定时看最近一轮 AI 改动，`git diff`）→ ② 逐条过四张表，**每条命中必须答上判据问句**，答不上就不报，误报比漏报更浪费用户时间 → ③ 只删多余部分，不顺手重构、不顺手改无关代码。

审的是**这一版代码多出来的东西**，不是历史包袱。看到一段烂代码但判断不出它是不是本轮变多的，先问「这些是这次新写的，还是原来就有的」，或先看 `git diff`。长期演进的遗留结构不归本 skill（那是重构立项），拿四张表去套只会报出一堆没法动的条目。

### 一、代码本体

| 术语 | 判据问句 | 修法 |
|---|---|---|
| 镀金（gold plating） | 需求／指令里有这条吗？ | 删掉没被要求的功能 |
| 过度防御 | 这个分支在现有调用方契约下能走到吗？ | 删不可能发生的判空／兜底／吞异常 catch |
| 投机泛化 | 第二个调用方存在吗？ | 只用一次的抽象合回调用处 |
| 过度配置化 | 它历史上改过吗？一年内会改吗？ | 配置项收回为常量 |
| 兼容性包袱 | 旧值／旧接口真的还在某处存活吗？ | 删迁移代码与兼容分支（同名同义自然承接，读不到走默认值） |
| 边界通胀 | 调用方契约允许这个值吗？ | 删与不变量矛盾的分支 |
| 占位残留 | 今天谁会调用它？ | 删 TODO 注释、无调用方的 stub、「将来可能用到」的参数 |

### 二、注释与文档

| 术语 | 判据问句 | 修法 |
|---|---|---|
| 复读注释 | 删掉注释，信息有损失吗？ | 删；只留「为什么」与非显而易见的约束 |
| 变更史注释 | 出现了「改为／之前是／本次新增」吗？ | 删（历史归 git 与 commit message） |
| 教科书头注 | 头注里有一句代码本身说不出来的话吗？ | 没有就整段删 |

### 三、提示词与对外文案

| 术语 | 判据问句 | 修法 |
|---|---|---|
| 画蛇添足 | 读者看到这句时，这件事大概率已经发生了吗？ | 删（如请求失败后建议改用搜索——读者多半刚从搜索进来） |
| 过时引用 | 提到的工具／命令／参数还存在吗？（grep 验证） | 改成现名 |
| 受众错位 | 这段文字的目标读者需要知道这句吗？ | 实现解释从用户文案删除，挪进对话回复 |
| 自证实现 | 这句影响对方下一步做什么吗？（「返回时会报告…」） | 不影响就删 |
| 平行重复 | 同一事实改规则时要同步改几处？ | 收敛为一处，其余只留指引 |
| 短文本跑长 | 这串字是按钮、标签、标题、菜单项、表头一类的固定长度处吗？ | 按钮、菜单项、标签控制在 2–6 字，写核心动词或名词；条件、宾语、原因移到附近说明或 tooltip。标题可长于控件，但也不写完整句子 |
| 标签带括号 | 括号里那句，是这个控件说不清自身功能才必需的吗？ | 删。只有单位、范围、版本这类区分项才留（`延迟（毫秒）`）；解释性的括号（`导出（仅包含本月）`）改成旁边说明 |

### 四、散文（文档／公告／发布文本）

| 术语 | 判据问句 | 修法 |
|---|---|---|
| 清嗓开场 | 这句除了宣告要开始说，还说了什么？ | 删（「众所周知」「随着…的发展」） |
| 伪洞察 | 它凭什么说「大多数人忽略」？ | 删，直接给判断 |
| 二元对立 | 读者原本真有那个误解吗？ | 直接从正面下判断（「不是 X，而是 Y」） |
| 重要性吹嘘 | 删掉这句评价，事实有损失吗？ | 删（「标志着关键时刻」「至关重要」） |
| 假深刻结尾 | 结尾是否只剩金句或比喻？ | 删，落在事实上 |
| 含糊归因 | 谁说的？ | 点名来源，或删（「专家认为」「研究表明」） |
| 同义词轮换 | 同一概念换了几种叫法？ | 重复用同一个词 |
| 空转句式 | 换成直白说法会丢信息吗？ | 删（「在…的道路上」） |
| 黑话 | 这个词在具体场景里指什么？ | 换成动作（「赋能／抓手／闭环／沉淀」） |
| 四字格堆砌 | 三个以上四字格并列，信息是新的吗？ | 概括成一句判断 |

成稿散文（文章、报告、公众号、汇报稿）不能只删，还要过下一节的去 AI 味。

---

## 去 AI 味（成稿散文）

白名单式改写：只处理下面列出的标记，**未命中任何规则的句子逐字保留**。不顺便润色，不换没问题的词，不调语气与详略。文章框架不在范围内——标题层级、章节顺序、段落数量与顺序、列表、表格、引用、代码块的位置原样保留。

**不承诺检测分数。** 降低 AIGC 检测率是题材专属任务（学术论文的语体与通用文章不同，有些做法互相冲突），不在本 skill 范围，遇到这类需求直说不适用。本 skill 只对「读者读着是否像 AI 写的」负责，不为迎合检测器而制造句长波动、拆段或注入口语词——那些属误伤区，改完只会把文章弄坏。

流程：
1. 同目录若有写作风格文档（风格指南、语言特征分析、`语言DNA.md` 一类），先读它。**风格文档与本规则冲突时以风格文档为准**——那是目标作者的真实写法，不是 AI 痕迹。
2. 判体裁。对话体、口语体、文学体裁、学术／新闻／公文不按同一把尺子，不为「像人写的」强加「我／你」或短段落。
3. 逐条查下表，只改命中处，改动限制在解决该问题所需的最小范围。
4. 按 `references/ai-tone-rules.md` 的验收清单复查后输出。

下面的表只管触发标记与改法，**每条都有自己的豁免**（法规条目、操作步骤、引语、作者本人的标点习惯……）。命中某条后先读 `references/ai-tone-rules.md` 里该条的「不改」栏再动手，误伤几乎全在这些边界上。

| # | 信号 | 触发标记 | 改法 | 实测倍率 |
|---|---|---|---|---|
| 1 | 翻案腔 | 「不是…而是…」「与其说…不如说…」「看似…实则…」「你以为…其实…」 | 直接从正面下判断，先给判断再给依据 | 3.4× |
| 2 | 顿号罗列过密 | 一个分句内两个以上顿号，连起三项以上并列 | 能概括就概括；必须逐项时改变其中一项的句法 | 1.8× |
| 3 | 相邻句结构同款 | 相邻两句以上逗号数相同、成分顺序相同、长度接近 | 打散其中一句的句法（合并／拆分／换语序） | 2.0× |
| 4 | 破折号滥用 | 破折号制造停顿后揭晓，或插入不必要的补充 | 写成完整句子，或改逗号、句号 | 3.0× |
| 5 | 冒号滥用 | 冒号前是「一句话总结」「核心是」类提示语；或整行只说「下面有列表」 | 提示语不承载信息就删，承载就换标点；空转句删掉让列表接上文 | 3.8× / 9.4× |
| 6 | 序数词当小标题 | 小标题连续三个以上以「一、二、三」或「第一、第二」编号 | 删编号，保留小标题文字 | 3.1× |
| 7 | 拟人化喻体 | 「像／相当于 + 一个／一位 + 职业角色」，带褒义修饰或后接「不仅…更…」 | 换成这东西实际做了什么 | 7.3× |
| 8 | 概括盖掉已有数据 | 「显著提升」「大幅增长」盖住同段已有的具体数值、时间或对象 | 把已有具体值提上来；原文没数据只恢复动词，不许编数字 | 反向（人类 2.8×） |
| 9 | 起手式 | 「说白了」「说穿了」「先说结论」 | 删掉，直接给判断 | 3.2× |
| 10 | 翻译腔（仅五种） | ①中心名词前修饰超十五字 ②「当…时，」开头 ③句首「对于…来说／就…而言」壳 ④句首「然而／因此／此外」 ⑤「这意味着」式复述句 | 拆成两个分句／删「当」「时」／把对象放到主语位／连接词移到主谓之间／并入前一句 | 2.6–5.3× |
| 11 | 段首零回指评论 | 非首段以「值得注意的是」「关键在于」「听起来」等评论语开头，整句无「这／那／其／此」回指 | 补一个回指词，多数情况加「这」字就够 | 4.4× |

翻译腔只有列出的五种够格，其余凭语感扩大范围一律撤销。

## 输出格式

按术语分组报告，每条：`文件:行号 + 术语 + 判据答案（一句话） + 最小修法`。没有问题就直说「未发现命中项」，不硬凑。

## 元规则

- 同一条术语在同一项目被认可过 **3 次以上** → 说明它是生成期就该守住的规则，提醒用户升格进该项目的 AGENTS.md，不要只等审查时才提出来。
- 本清单只管「删多余」与「去 AI 味」，不管风格偏好（命名、缩进、句式长短、书面或口语是偏好，不是 slop）。
